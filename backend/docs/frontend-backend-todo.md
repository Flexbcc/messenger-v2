# Frontend ↔ Backend — открытые задачи

Документ фиксирует то, что клиент **не может** честно показать или гарантировать без доработки бэкенда / протокола.

## Безопасность и транспорт

| Задача | Почему нужен бэкенд | Текущий UI |
|--------|---------------------|------------|
| Проверка TLS/mTLS на клиенте | Нужен pinning / сертификатная цепочка от gateway | «TLS/mTLS: не проверено клиентом» |
| Server-side delivery ACK | Статус `delivered` сейчас client-side / optimistic | Иконки доставки в чате |
| Подтверждение E2E с сервером | Клиент видит только локальные ключи | «Ключи на устройстве» |

## Устройства и сессии

| Задача | Почему нужен бэкенд | Текущий UI |
|--------|---------------------|------------|
| IP / гео последнего входа | Нет полей в `DeviceInfo` | Скрыто |
| Push-токен revoke при logout | Нужен endpoint | Локальный logout только |
| Recovery key на сервере | Нет backup API | Только локальный vault |

## Сообщения и синхронизация

| Задача | Почему нужен бэкенд | Текущий UI |
|--------|---------------------|------------|
| Read receipt через сервер | Сейчас control-message E2E | Статус «прочитано» |
| Очередь offline на relay | Нужен durable outbox + sync API | Локальная очередь failed/scheduled |
| История с других устройств | Нужен multi-device sync | Только текущее устройство |

## Инфраструктура

| Задача | Почему нужен бэкенд | Текущий UI |
|--------|---------------------|------------|
| Единый health для всех сервисов | Разные порты, нет агрегата | Пинг по URL из `config.dart` |
| WebSocket reconnect token | Сессия может протухать | Кнопка «Переподключить» |

## Принципы

- Не показывать «абсолютную защиту» без серверного подтверждения.
- Любой новый security-badge должен ссылаться на проверяемый факт (локальный или с API).
- Перед добавлением поля в Security Dashboard — сначала контракт API.
