# 0203. Маршрутизация

## Статус
Черновик

## Назначение
Как Packet находит путь от отправителя к получателю через узлы
инфраструктуры.

## Модель маршрутизации
Порядок попыток доставки, от самого быстрого к самому надёжному пути:
1. **Прямая доставка** Home Node отправителя → Home Node получателя, если между ними существует прямой сетевой путь.
2. **Через Relay Node**, если прямой путь недоступен (NAT, файрвол, разные операторы инфраструктуры без прямой связности) — см. [0601_RELAY_NODE.md](0601_RELAY_NODE.md).
3. **Через Storage Node** получателя, если сама Home Node получателя или все её активные устройства недостижимы — см. [0202_DELIVERY.md](0202_DELIVERY.md).

## Разрешение адреса получателя
Адрес Home Node получателя разрешается через Discovery Node по UserID (см.
[0604_DISCOVERY_NODE.md](0604_DISCOVERY_NODE.md)). Результат — подписанная
запись, которую отправитель проверяет самостоятельно, не доверяя
транспортному каналу, по которому она была получена (Zero Trust).

## Multi-hop маршрутизация
Packet может пройти через несколько Relay Node, если ни один из них не
имеет прямой связности со следующим узлом на маршруте. Каждый промежуточный
Relay Node видит только предыдущий и следующий хоп (см. `sender_ref` в
[0201_PACKETS.md](0201_PACKETS.md)), а не полный маршрут и не итоговый
источник/получателя за пределами соседних хопов.

## Обработка недостижимости узла
- Если конкретный Relay Node недоступен, отправитель/предыдущий хоп выбирает следующий по списку, полученному от Discovery Node.
- Если недостижима сама Home Node получателя (не только его устройства), доставка откладывается и повторяется с backoff, пока Home Node не вернётся в сеть, либо, если Home Node зарегистрировала новый адрес — маршрут пересчитывается по свежей Discovery-записи.

## Приватность маршрутизации
Relay Node не имеет доступа к содержимому Packet (payload зашифрован
end-to-end, см. [0300_CRYPTO.md](0300_CRYPTO.md)) и не обязан знать
конечный UserID отправителя или получателя — для маршрутизации достаточно
адреса следующего хопа. Это ограничивает объём метаданных, доступных
любому отдельному Relay Node, до пары «предыдущий хоп → следующий хоп» и
временной метки прохождения пакета. Полное устранение метаданных о факте и
времени связи (например, посредством mix-сетей) не является целью первой
версии протокола — это осознанный компромисс (см.
[0005_DESIGN_PHILOSOPHY.md](0005_DESIGN_PHILOSOPHY.md)).
