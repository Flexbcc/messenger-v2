# 0302. Модель угроз (детальная)

## Статус
Черновик

## Назначение
[0300_CRYPTO.md](0300_CRYPTO.md) → «Модель угроз» формулирует базовые
допущения одним абзацем. Этот документ раскрывает их до уровня, пригодного
для проектирования конкретных механизмов защиты и для внешнего
криптографического аудита: какие активы защищаются, какими возможностями
обладает атакующий в каждой позиции сети, и что явно остаётся вне рамок
протокола.

## Активы (что защищаем)
| Актив | Описание |
|---|---|
| Содержимое Message | Текст, файлы, реакции — должно быть нечитаемо для всех, кроме отправителя и получателей Conversation |
| Ключи E2EE | Identity-ключи, prekey, sender key — компрометация раскрывает содержимое переписки |
| Метаданные связи | Кто с кем общается, когда, как часто, какого объёма сообщения |
| Членство в группе | Состав участников группы Conversation |
| Доступность | Возможность отправить/получить сообщение при доступной сети |
| Доступность инфраструктуры | Возможность узла выполнять свою роль без перегрузки атакующим (DoS) |

## Позиции атакующего

### 1. Пассивный наблюдатель сети
**Возможности:** видит зашифрованный трафик между Client и Node или между
Node (транспортное шифрование, см. [0300_CRYPTO.md](0300_CRYPTO.md) →
Шифрование на уровне транспорта), может анализировать тайминг и размеры
пакетов.
**Защищено:** содержимое Message (E2EE + транспортное шифрование).
**Не защищено полностью:** сам факт активности соединения (что устройство
online) может быть заметен по паттерну трафика на транспортном уровне —
это остаточный риск, минимизация которого (константный трафик,
padding) не входит в первую версию протокола.

### 2. Скомпрометированный или недобросовестный Relay Node
**Возможности:** видит предыдущий/следующий хоп маршрута, время и размер
Packet (см. [0201_PACKETS.md](0201_PACKETS.md)); может отказаться
пересылать Packet (DoS в рамках одного маршрута) или пересылать его с
задержкой.
**Защищено:** содержимое Message (E2EE), Identity отправителя/получателя за
пределами соседних хопов (см. [0203_ROUTING.md](0203_ROUTING.md) →
приватность маршрутизации).
**Не защищено:** полный граф связи не строится с одного Relay Node, но
Relay, наблюдающий трафик достаточно долго и в достаточном объёме
маршрутов, теоретически может накапливать статистику по таймингу — это
принятый компромисс (см. [0005_DESIGN_PHILOSOPHY.md](0005_DESIGN_PHILOSOPHY.md)).
**Отказ пересылать Packet** — компенсируется повторной отправкой через
другой Relay Node (см. [0202_DELIVERY.md](0202_DELIVERY.md)), а не
криптографически — это вопрос доступности, а не конфиденциальности.

### 3. Скомпрометированный или недобросовестный Storage Node
**Возможности:** хранит E2EE-шифротекст непрочитанных сообщений, видит
объём буфера на получателя и время постановки/выемки.
**Защищено:** содержимое Message (шифротекст без ключа бесполезен).
**Не защищено:** может отказаться хранить/выдать Packet (DoS для
конкретного офлайн-получателя) — компенсируется тем, что Home Node может
использовать альтернативный Storage Node (см.
[0602_STORAGE_NODE.md](0602_STORAGE_NODE.md)); может удалить Packet раньше
срока — обнаруживается получателем как отсутствие ожидаемого сообщения, но
не восстанавливается без переотправки отправителем (принятый компромисс
доступности при недоверенной инфраструктуре).

### 4. Скомпрометированный или недобросовестный Media Node
**Возможности:** хранит зашифрованные объекты, видит размер файла и
частоту обращений к нему.
**Защищено:** содержимое файла (клиентское шифрование до загрузки, см.
[0603_MEDIA_NODE.md](0603_MEDIA_NODE.md)).
**Не защищено:** факт существования и размер объекта; может отказать в
раздаче (DoS) — не влияет на конфиденциальность уже полученных копий у
других получателей.

### 5. Скомпрометированный или недобросовестный Discovery Node
**Возможности:** видит, кто и с какой частотой запрашивает разрешение
адреса конкретных UserID — потенциально самый информативный источник
метаданных социального графа в системе (см.
[0604_DISCOVERY_NODE.md](0604_DISCOVERY_NODE.md) → Приватность
обнаружения).
**Защищено:** содержимое ответа проверяется по подписи Client
самостоятельно (Zero Trust) — Discovery Node не может незаметно подменить
адрес Home Node без обнаружения (подпись не сойдётся).
**Не защищено:** сама история запросов на разрешение — это явный
остаточный риск первой версии протокола, зафиксированный как направление
будущей работы (private set intersection и подобные техники).

### 6. Скомпрометированная или недобросовестная Home Node (своя или чужая)
**Возможности:** видит метаданные доставки (кому/когда доставлен Packet),
может отказать в обслуживании собственных пользователей (DoS) или
намеренно не доставить/не поставить в Storage Node сообщение.
**Защищено:** содержимое Message (E2EE) недоступно даже собственной Home
Node пользователя.
**Не защищено:** факт присутствия пользователя онлайн в моменты его
подключения к собственной Home Node — неизбежное следствие того, что Home
Node физически обслуживает соединение; минимизируется только выбором
доверенного оператора Home Node (в пределе — собственного, self-hosted).

### 7. Скомпрометированное устройство пользователя (Device)
**Возможности:** полный доступ к расшифрованному содержимому и локальным
ключам на этом конкретном устройстве.
**Защищено:** переписка на других Device того же пользователя и у
собеседников — не раскрывается ретроактивно при условии своевременного
отзыва ключа (см. [0300_CRYPTO.md](0300_CRYPTO.md) → Отзыв ключей).
**Явно вне рамок модели угроз:** компрометация самого устройства
(вредоносное ПО, физический доступ, эксплойты ОС) — протокол не может
защитить содержимое на устройстве, которому пользователь сам
предоставляет доступ к расшифрованным данным.

### 8. Недобросовестный участник группы
**Возможности:** имеет доступ к sender key всех участников группы, пока
состоит в ней; может пересылать расшифрованные сообщения за пределы
группы.
**Защищено:** после исключения из группы участник не получает новые
sender key (см. [0301_GROUP_MESSAGING.md](0301_GROUP_MESSAGING.md) →
Удаление участника) — не читает будущую переписку.
**Явно вне рамок модели угроз:** пересылка уже полученных сообщений за
пределы E2EE-периметра — фундаментальное ограничение любой системы
группового шифрования, не специфичное для этого протокола.

### 9. Атакующий, контролирующий множество узлов (Sybil)
**Возможности:** при контроле над достаточным числом Relay/Discovery Node
атакующий увеличивает шанс оказаться на маршруте нескольких хопов одной
передачи и тем самым — шанс сопоставить метаданные тайминга на разных
хопах (атака корреляции трафика, аналогичная известным атакам на
mix-сети/Tor).
**Не защищено:** протокол первой версии не проектирует специальную защиту
от sybil-корреляции трафика (например, добавочные задержки, decoy-трафик)
— явный принятый компромисс между устойчивостью к деанонимизации и
задержкой доставки (см. [0005_DESIGN_PHILOSOPHY.md](0005_DESIGN_PHILOSOPHY.md)).

## Явно вне рамок модели угроз протокола
- Компрометация операционной системы или физическая компрометация Device.
- Целенаправленная deanonymization через долгосрочный анализ трафика при глобальном пассивном наблюдателе (нужны mix-сети/decoy-трафик — не в первой версии).
- Пересылка получателем расшифрованного содержимого за пределы E2EE-периметра.
- Юридическое принуждение оператора конкретного Node — протокол защищает содержимое даже в этом случае (E2EE), но не может скрыть сам факт эксплуатации узла этим оператором.

## Требования к аудиту
Перед стабилизацией любой `MAJOR`-версии протокола, использующей схемы из
[0300_CRYPTO.md](0300_CRYPTO.md) и [0301_GROUP_MESSAGING.md](0301_GROUP_MESSAGING.md),
обязателен независимый внешний аудит, покрывающий все девять позиций
атакующего выше. Результаты аудита и принятые/отклонённые рекомендации
фиксируются через [ADR](ADR/README.md).
