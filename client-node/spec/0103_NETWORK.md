# 0103. Сеть

## Статус
Черновик

## Назначение
Сетевая топология, транспортные протоколы и подходы к обеспечению
связности узлов и клиентов.

## Топология сети
Гибридная топология: клиенты подключаются к своей Home Node
«звездой» (каждое Device — отдельное соединение), а сами Node образуют
mesh-сеть через Federation — любой Node может установить соединение с
любым другим Node, если это разрешено его ролью (см.
[0101_COMPONENTS.md](0101_COMPONENTS.md) → Матрица взаимодействий).
Единого центрального маршрутизатора не существует (Decentralization
First).

## Транспорт
Референсный выбор — QUIC (UDP) как основной транспорт, с TCP+TLS 1.3 как
резервным вариантом при недоступности UDP (сети с жёсткой фильтрацией).
QUIC даёт мультиплексирование потоков и быстрое переустановление
соединения после смены сети, что напрямую поддерживает Offline First на
мобильных клиентах. Протокол (0200) не зависит от конкретного транспорта —
это конкретный, заменяемый выбор реализации (Replaceable Everything), а не
часть спецификации протокола.

## NAT traversal
Клиент-клиентские прямые соединения (там, где это применимо) используют
стандартные открытые механизмы ICE/STUN, с Relay Node в роли TURN-подобного
резервного пути, когда прямое соединение недостижимо. В базовом сценарии
клиент всегда может достичь сети через исходящее соединение к своей Home
Node — NAT traversal является оптимизацией задержки, а не обязательным
условием работы.

## Обнаружение узлов
Discovery Node предоставляет каталог доступных узлов и их Capability
(Relay/Storage/Media/Discovery). Подробности — см.
[0604_DISCOVERY_NODE.md](0604_DISCOVERY_NODE.md).

## Отказоустойчивость и деградация сети
- При потере соединения клиент продолжает работать в offline-режиме, накапливая исходящие Packet в локальной очереди (Queue).
- При недоступности одного Relay Node клиент/Home Node выбирает следующий доступный из списка, полученного от Discovery Node.
- При временной недоступности Home Node получателя используется Storage Node как промежуточный буфер (см. [0102_DATA_FLOW.md](0102_DATA_FLOW.md)).
- Ни один сценарий деградации сети не должен приводить к потере ещё не подтверждённых сообщений — гарантии доставки описаны в [0202_DELIVERY.md](0202_DELIVERY.md).
