# Задача: описать и реализовать базовый UI-дизайн мессенджера

Нужно заложить визуальную дизайн-систему для Flutter-приложения мессенджера.

Стиль: iPhone / iOS-like, минимализм, чёрно-белая база, аккуратные акцентные цвета только для важных действий и статусов.

Цель: получить не просто отдельные экраны, а единую UI-систему, на которой дальше будут строиться все экраны приложения.

---

# 1. Общий стиль

Приложение должно выглядеть как современный iOS-мессенджер:

- чистый белый фон;
- много воздуха;
- тонкие разделители;
- аккуратные скругления;
- минимум визуального шума;
- чёрный как основной цвет действия;
- серый для второстепенного текста;
- цветные акценты только для статусов, ошибок, успеха и ссылок.

Интерфейс должен быть спокойным, дорогим, минималистичным.

Не использовать яркие градиенты, тяжёлые тени, декоративные фоны, кислотные цвета.

---

# 2. Цветовая система

Создать файл/модуль с дизайн-токенами цветов.

## Базовые цвета

```text
backgroundLight: #FFFFFF
backgroundDark:  #000000

surfaceLight:    #F7F7F7
surfaceDark:     #1C1C1E

textPrimary:     #000000
textInverse:     #FFFFFF

textSecondary:   #8E8E93
textMuted:       #C7C7CC

borderLight:     #E5E5EA
borderDark:      #2C2C2E
```

## Акцентные цвета

```text
accentBlue:      #0A84FF  // действия, ссылки, активные элементы
successGreen:    #30D158  // онлайн, успех
dangerRed:       #FF453A  // ошибка, удаление, пропущенный звонок
warningYellow:   #FFD60A  // предупреждение, внимание
```

## Правила использования цвета

- Чёрный используется для основного текста и главных кнопок.
- Белый используется для фона и текста на тёмных элементах.
- Синий используется только для интерактивных акцентов: ссылки, активные действия, выбранные состояния.
- Зелёный используется только для успеха и статуса онлайн.
- Красный используется только для ошибок, удаления, опасных действий.
- Жёлтый используется только для предупреждений.
- Серый используется для второстепенной информации.

---

# 3. Типографика

Использовать системный iOS-стиль.

Основной шрифт: SF Pro / системный шрифт платформы.

Если SF Pro недоступен, использовать системный Flutter font fallback.

## Размеры

```text
largeTitle: 28 / Bold
title:      17 / Semibold
subtitle:   15 / Semibold
body:       17 / Regular
secondary:  15 / Regular
caption:    13 / Regular
```

## Правила

- Заголовки короткие и плотные.
- Основной текст читаемый, не мельчить.
- Второстепенный текст всегда серый.
- Не использовать больше 2–3 размеров текста на одном экране.
- Важные действия выделять весом шрифта, а не цветом.

---

# 4. Размеры и отступы

Использовать базовую сетку 4pt.

```text
gridBase: 4
screenPadding: 16
cardPadding: 16
smallGap: 8
mediumGap: 12
largeGap: 16
sectionGap: 24

borderRadiusSmall: 8
borderRadiusMedium: 12
borderRadiusLarge: 16

rowHeight: 56
inputHeight: 44
buttonHeight: 44
bottomNavHeight: 64
```

## Правила

- Основной горизонтальный отступ экрана: 16pt.
- Между крупными секциями: 24pt.
- Между элементами внутри карточки: 8–12pt.
- Скругление карточек и полей: 12pt.
- Кнопки и поля не ниже 44pt по высоте.

# 5. Базовые компоненты

Нужно создать переиспользуемые UI-компоненты.

## Primary Button

Главная кнопка.

Внешний вид:

- фон чёрный;
- текст белый;
- высота 44;
- radius 12;
- текст 17 Semibold.

Использование:

- основное действие;
- подтверждение;
- создание;
- отправка.

## Secondary Button

Вторичная кнопка.

Внешний вид:

- белый фон;
- чёрная рамка;
- чёрный текст;
- высота 44;
- radius 12.

Использование:

- отмена;
- альтернативное действие;
- переход без критичности.

## Danger Button

Опасное действие.

Внешний вид:

- белый фон;
- красный текст;
- без агрессивной заливки;
- можно использовать красную рамку только в критических случаях.

Использование:

- удалить;
- выйти;
- завершить все сессии;
- очистить историю.

## Text Field / Message Input

Поле ввода.

Внешний вид:

- высота 44;
- radius 12;
- фон #F7F7F7;
- placeholder серый;
- слева иконка вложений;
- справа микрофон или отправка.

Для поля сообщения:

- слева кнопка вложений;
- центр: текст;
- справа: микрофон, если текст пустой;
- справа: отправка, если текст есть.

## Chip / Tag

Небольшой тег.

Внешний вид:

- светло-серый фон;
- radius 999;
- текст 13–15;
- optional close icon.

Примеры:

- Работа;
- Личные;
- E2EE;
- Онлайн;
- Архив.

## Status Dot

Индикатор статуса.

- online: зелёная точка;
- offline: серая точка;
- error: красная точка;
- warning: жёлтая точка.

## Unread Badge

Бейдж непрочитанных.

Внешний вид:

- круг;
- чёрный фон;
- белый текст;
- минимальный размер 22x22;
- текст 13 Semibold.

## Avatar

Аватар пользователя.

Варианты:

- изображение;
- инициалы;
- системная иконка группы.

Размеры:

```text
avatarSmall: 24
avatarMedium: 40
avatarLarge: 88
```

## Switch

Переключатель в стиле iOS.

- активный: чёрный фон;
- неактивный: светло-серый фон;
- круглый бегунок белый.

# 6. Нижняя навигация

Нижняя навигация содержит 4–5 разделов:

```text
Чаты
Звонки
Контакты
Настройки
```

Можно добавить центральное действие “Создать” позже, но для MVP лучше оставить 4 пункта.

## Правила

- Активный пункт: чёрная иконка + чёрный текст.
- Неактивный пункт: серый.
- Иконки outline.
- Подписи короткие.
- Нижняя навигация всегда одинаковая на главных экранах.

---

# 7. Экран “Чаты”

Назначение: главный экран со списком переписок.

## Элементы

Верхняя часть:

- заголовок “Чаты”;
- справа кнопка “+” для нового чата;
- ниже поле поиска.

Список чатов:

Каждая строка содержит:

- аватар;
- имя чата;
- последнее сообщение;
- время последнего сообщения;
- бейдж непрочитанных;
- статус “печатает...” при необходимости;
- иконку mute/закрепления позже.

Пример строки:

```text
[avatar] Алексей              09:41
         Привет! Как дела?      [2]
```

## Поведение

- Tap по строке открывает диалог.
- Swipe left: дополнительные действия.
- Swipe right: отметить прочитанным / непрочитанным.
- Pull to refresh: обновить список.
- Search фильтрует чаты локально.

## Пустое состояние

Если чатов нет:

- крупная иконка;
- текст “Пока нет чатов”;
- кнопка “Создать чат”.

# 8. Экран “Диалог”

Назначение: экран переписки.

## Верхняя панель

Содержит:

- back button;
- avatar;
- имя собеседника/группы;
- статус: онлайн / был(а) недавно / печатает;
- справа кнопка действий или звонка.

## Область сообщений

Типы сообщений:

- входящее текстовое;
- исходящее текстовое;
- голосовое;
- файл;
- изображение;
- системное событие;
- реакция.

## Внешний вид сообщений

Входящие:

- светлый bubble;
- чёрный текст;
- выравнивание слева.

Исходящие:

- чёрный bubble;
- белый текст;
- выравнивание справа.

Время:

- маленькое;
- серое;
- внутри или рядом с bubble.

Статус отправки:

- отправляется;
- отправлено;
- доставлено;
- прочитано;
- ошибка.

## Нижняя панель ввода

Содержит:

- кнопку вложений;
- поле сообщения;
- кнопку микрофона;
- кнопку отправки при наличии текста.

## Поведение

- Swipe message right: ответить.
- Long press: открыть меню действий.
- Tap по файлу: открыть preview.
- Tap по avatar/name: открыть информацию о чате.
- Keyboard не должен ломать layout.

# 9. Экран “Звонки”

## Элементы

Верхняя часть:

- заголовок “Звонки”;
- segmented control:
  - Все;
  - Пропущенные.

Список:

Каждая строка содержит:

- аватар;
- имя;
- тип звонка;
- время;
- иконку звонка справа.

## Поведение

- Tap по строке открывает детали или сразу звонит.
- Tap по иконке звонка запускает звонок.
- Фильтр “Пропущенные” показывает только missed calls.

# 17. Жесты и навигация

Использовать привычные iOS-паттерны.

## Жесты

```text
Tap
Открыть / выбрать

Long press
Открыть контекстное меню

Swipe left
Дополнительные действия

Swipe right
Назад / ответить / отметить

Pull down
Обновить

Drag down modal
Закрыть bottom sheet
```

## Правила

- Все жесты должны иметь видимый fallback через кнопки.
- Нельзя делать важное действие доступным только через жест.
- Удаление всегда требует подтверждения.

# 18. Состояния интерфейса

Для каждого компонента нужно поддерживать состояния:

```text

selected
disabled
```

## Примеры

- loading: spinner или skeleton;
- error: красный текст + retry;
- empty: иконка + пояснение + действие;
- offline: маленький статус вверху или под заголовком.

# 20. Ограничения

Не использовать:

- яркие градиенты;
- Material Design-heavy стиль;
- большие тени;
- декоративные фоны;
- случайные цвета;
- сложные анимации на первом этапе;
- бизнес-логику внутри UI-виджетов.

Не реализовывать пока:

- реальную авторизацию;
- реальную отправку сообщений;
- реальное E2EE;
- WebSocket;
- push;
- звонки.

Сейчас задача — UI foundation.

---

# 21. Критерии готовности

Задача считается выполненной, если:

- создана единая тема приложения;
- все цвета вынесены в токены;
- все размеры вынесены в токены;
- есть базовые компоненты;
- есть основные mock-экраны;
- навигация между экранами работает;
- UI выглядит цельно;
- экраны похожи на iOS-style messenger;
- нет случайных цветов и отступов;
- mock-данные отделены от UI;
- код готов к последующему подключению backend.
