# Изоляция сетей и реальное состояние архитектуры

## Цель

Клиент может работать с несколькими независимыми сетями:

1. **Централизованная** — управляемый кластер с известными Home, Discovery,
   Relay и Media узлами.
2. **Децентрализованная** — сеть независимых Home-узлов с discovery,
   федерацией и пользовательскими нодами.

Обе сети могут использовать один протокол и один клиент, но не разделяют
идентичность, ключи, контакты, настройки аккаунта или историю.

## Что уже соответствует исходной идее

- Клиент выполняет локальные настройки, уведомления и большую часть политик.
- Сообщения шифруются на клиенте; сервер получает ciphertext.
- Есть Home, Discovery, Relay, Media и Storage роли.
- Есть bootstrap по приглашению, резервные Home-узлы и failover.
- QR контакта больше не содержит профиль: только подписанный одноразовый
  handshake и публичные ключи.
- PIN, дополнительный PIN и секретные функции локальны и разделены по аккаунтам.
- Локальные настройки разделены по аккаунтам и переживают повторный вход.

## Реальные проблемы

### P0 — ключи не изолированы по сети

Сейчас `AuthKeyPair` и Signal identity сохраняются в глобальных ключах
установки (`auth_keypair_seed_b64`, `signal_identity_b64`). Смена Home/cluster
не создаёт новую идентичность. Это позволяет связать одного пользователя между
двумя независимыми сетями и нарушает требование разделения.

### P0 — конфигурация сети является одиночной

`BootstrapStore.current` представляет одну активную сеть. Новое приглашение
заменяет текущую конфигурацию. Нет реестра сетей, отдельного состояния входа и
безопасной транзакции переключения.

### P0 — локальные пространства учитывают аккаунт, но не сеть

Настройки и PIN имеют namespace по `user_id`, но не по `network_id`. Если две
сети выдали одинаковый идентификатор, локальные данные могут пересечься.
Требуемый namespace: `network_id + local_user_id + device_id`.

### P0 — временная серверная авторизация не соответствует целевой модели

В Home Node остаётся ADR-0007: телефон/login/email + пароль и серверный профиль.
Это временный bridge, а не финальная identity-модель. Целевой вход — challenge
и подпись отдельным ключом текущей сети.

### P1 — Home Node знает больше метаданных, чем требуется маршрутизатору

Текущие таблицы хранят conversation graph, sender, content type, timestamps,
delivery state и долговременный ciphertext. Нужно отдельно определить минимум,
TTL и обязательное удаление после доставки.

### P1 — QR завершает только первый этап

Handshake подписан и сохраняет проверенные публичные ключи. Ещё нужен второй
этап: encrypted profile card с явным перечнем полей, которыми пользователь
разрешил поделиться.

### P1 — часть E2EE пока упрощена до адресации на пользователя

В Signal-коде остаётся логический `deviceId = 1`. Для настоящей изоляции и
multi-device каждый конверт должен адресоваться конкретному устройству.

### P2 — переключение Home смешано с переключением сети

Failover между Home внутри одной сети должен сохранять identity. Переход в
другую сеть обязан менять identity и локальный namespace. Сейчас эти операции
не разделены достаточно строго.

## Целевая модель Network Profile

Каждая сеть хранится как отдельный профиль:

```text
NetworkProfile
  network_id
  kind: centralized | decentralized | experimental
  display_name
  trust_anchor_public_key
  cluster_id
  home_urls[]
  discovery_url
  media_url
  local_user_id
  local_device_id
  user_identity_key_ref
  auth_keypair_ref
  signal_identity_ref
  created_at
  last_used_at
```

`network_id` нельзя строить только из URL. Он должен вычисляться из
криптографического trust anchor / подписанного network manifest. Иначе смена
домена или подмена DNS будет выглядеть как та же сеть.

## Правила ключей

- Для каждой сети создаётся отдельный корневой ключ пользователя.
- `local_user_id` внутри сети выводится из публичной части этого ключа либо
  жёстко связывается с ней подписанной записью.
- Каждое устройство получает отдельный Ed25519 auth keypair, подписанный
  корневым ключом пользователя этой сети.
- Для каждого устройства и сети создаётся отдельная Signal identity.
- Prekeys, сессии и sender keys принадлежат только одной сети.
- PIN можно оставить устройственно-аккаунтным, но namespace также включает
  `network_id`, чтобы одинаковые `user_id` не пересекались.
- Ключи нельзя копировать между сетями автоматически.
- Экспорт идентичности явно указывает сеть и не импортируется в другую сеть.

## Переключатель для тестов и экспериментов

В разделе «Разработчик → Сети»:

- список добавленных сетей;
- текущая сеть и её тип;
- кнопка «Добавить тестовую сеть» по invite/QR;
- переключение только после закрытия активных соединений и блокировки vault;
- явная отметка «Отдельная идентичность и ключи»;
- удаление тестовой сети с отдельным подтверждением;
- возможность сбросить только данные выбранной сети;
- production-сеть нельзя случайно заменить custom URL.

Экспериментальный переключатель доступен только в debug/developer mode.

## Безопасная последовательность переключения

1. Завершить звонки и остановить realtime текущей сети.
2. Заблокировать скрытое хранилище и очистить состояние в памяти.
3. Сохранить session текущего Network Profile.
4. Активировать namespace целевой сети.
5. Загрузить её auth и Signal keys.
6. Применить её bootstrap и проверить подпись network manifest.
7. Восстановить локальную сессию либо показать отдельный вход.
8. Только после этого подключать realtime и загружать диалоги.

При ошибке переключение откатывается целиком к предыдущему профилю.

## Порядок реализации

1. Ввести `NetworkProfileStore` и стабильный подписанный `network_id`.
2. Расширить все namespaces: `network_id + user_id`.
3. Добавить network-scoped user identity и подписанные device identities.
4. Перенести AuthKeyPair, Signal identity, prekeys и sessions в network scope.
5. Разделить `switchHomeWithinNetwork` и `switchNetwork`.
6. Добавить developer UI для двух тестовых сетей.
7. Покрыть тестами невозможность расшифровать или открыть данные другой сети.
8. После миграции удалить ADR-0007 bridge и лишние серверные поля.

## Критерий готовности

Один клиент подключён к сети A и сети B. В каждой сети у него другой
fingerprint. Контакты, PIN, настройки, Signal sessions и история A не видны в
B. Failover между Home A1 и A2 сохраняет fingerprint сети A. Переключение на B
всегда меняет fingerprint и локальное пространство.
