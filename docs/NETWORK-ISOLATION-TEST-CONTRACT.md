# Обязательный тестовый контракт изоляции сетей

Экспериментальный переключатель сетей нельзя включать в UI, пока все тесты
уровней L1–L4 не проходят без skip.

## L1 — криптографическая идентичность

- Один trust anchor всегда даёт один `network_id`.
- URL Home-ноды не участвует в вычислении `network_id`.
- A1 → A2 с одним trust anchor сохраняет user fingerprint.
- Сеть A и сеть B всегда получают разные user root keys.
- Device keys разных сетей различаются и подписаны root key своей сети.
- Повреждённый trust anchor, seed или signature отклоняется fail-closed.

## L2 — локальное хранение

- Namespace включает `network_id + user_id`.
- Одинаковый `user_id` в A и B не пересекает настройки.
- PIN, fake PIN, Signal identity, prekeys и sender keys разделены по сети.
- Контакты, QR-handshakes, черновики, кэш и скрытые чаты разделены по сети.
- Удаление данных B не изменяет A.
- Обычный выход и повторный вход в A восстанавливают только A.

## L3 — переключение

- A → B закрывает realtime A до подключения B.
- Секретный vault блокируется до смены namespace.
- Состояние в памяти A очищается до загрузки B.
- Ошибка подключения B полностью откатывает переключение к A.
- Failover A1 → A2 не считается сменой сети.
- Смена custom URL с другим trust anchor требует создания новой сети.
- Активный звонок блокирует переключение либо корректно завершается.

## L4 — end-to-end две сети

- Одно приложение регистрируется в централизованной A и децентрализованной B.
- Серверы A не получают ключи, токены или трафик B и наоборот.
- Ciphertext из A нельзя расшифровать ключами B.
- Контакт из A отсутствует в B до отдельного QR-обмена.
- Уведомление A содержит правильный network context и не открывает B.
- Push token не позволяет отправить событие другой сети.
- Резервное копирование и восстановление требуют явного выбора сети.

## Негативные и хаос-тесты

- Подмена network manifest и trust anchor.
- DNS/URL указывает на узел другой сети.
- Узел меняет trust anchor после первого подключения.
- Обрыв питания между деактивацией A и активацией B.
- Два быстрых конкурентных переключения.
- Истёкший invite/QR, повторное использование nonce.
- Повреждённое локальное хранилище одного Network Profile.
- Удалённая или недоступная Home-нода при возврате в сеть.

## Release gate

Экспериментальный UI разрешён только когда:

1. L1 и L2 проходят полностью.
2. Есть транзакционный switch с rollback и проходят L3.
3. В debug-сборке есть минимум один E2E A↔B из L4.
4. UI явно показывает network name и сокращённый fingerprint.
5. Ни один тест изоляции не помечен skip/flaky.
