Как это устроено

OUO не строится вокруг одного «главного сервера». У каждого компонента узкая роль, а компрометация отдельной ноды не должна автоматически раскрывать переписку или давать контроль над сетью.

  1. Устройство отправителя шифрует сообщение для устройств получателя.
  2. Home Node принимает ciphertext и выбирает доступный маршрут.
  3. Relay пересылает, а Storage временно буферизует сообщение, если адресат офлайн.
  4. Устройство получателя подтверждает доставку и расшифровывает сообщение локально.
Посмотреть путь сообщения по шагам →

Discovery

Bootstrap и подписанные сведения о нодах. Не владеет пользовательскими ключами.

Home Node

Подключения устройств, маршрутизация и доставка без доступа к plaintext.

Relay

Транзит между нодами; не считается доверенным получателем сообщения.

Storage

Краткоживущий офлайн-буфер для непрозрачных зашифрованных пакетов.

Что уже проверяется

Функции считаются готовыми только после воспроизводимой проверки.

  • E2EE-обмен между двумя настоящими тестовыми пользователями
  • локальные ключи, encrypted backup и разделение аккаунтов
  • основной PIN, fake PIN и режим-приманка
  • доставка через Home и временный Storage
  • управление несколькими своими нодами с телефона

Своя пользовательская нода

Ноду можно установить с локальной админ-панелью или без неё. В обоих режимах её можно отдельно сопрячь с телефоном владельца одноразовым кодом; это не даёт ноде доступа к переписке.

curl -fsSL https://www.ouoapp.ru/install-node.sh | bash

Перед запуском можно скачать и прочитать скрипт отдельно. Пакет ноды проверяется по SHA-256.

Важно: лабораторный HTTP-режим предназначен только для закрытого стенда. Публичная нода требует TLS и доступа к управлению через VPN или mTLS.
