# Network assistance: добровольная помощь частной ноды сети

> Статус: **модель + UI-модель в визуализаторе**.

## Назначение

Частная нода может добровольно помогать другим пользователям. Это **не** должно
включаться скрытно. По умолчанию — безопасный ограниченный режим.

## Роли

```
Personal only
Limited network assistance
Public relay
Temporary storage
Discovery helper
Witness
```

## Настройки пользователя

```
Помощь сети: включена / выключена

Разрешённые функции:
[ ] Relay
[ ] Временное хранение
[ ] Discovery
[ ] Witness
[ ] NAT assistance

Ограничения: CPU · RAM · Disk · Inbound/Outbound bandwidth · Monthly traffic ·
Connections · Parallel transfers · Schedule
```

Владелец должен видеть: какой трафик использует нода, сколько места занято,
сколько соединений обслуживается, какую роль выполняет, и как быстро отключить
помощь сети.

## Изоляция (принцип наименьших привилегий)

- Relay **не** читает User Library.
- Storage **не** получает ключи личных чатов.
- Community Worker ограничен отдельными ресурсами и **не** имеет доступа ко всему
  диску.
- Публичный сетевой процесс изолирован от административного API.

См. [threat-model](threat-model.md) §изоляция компонентов.

## Простые названия для пользователя

```
Network Assistance → Помощь сети
Relay              → Помогать передавать сообщения
Temporary Storage  → Временно хранить зашифрованные файлы
Capacity           → Доступные ресурсы
Node Overloaded    → Устройство занято, помощь сети приостановлена
```

Экспертный режим показывает реальные технические названия.

## Реализовано в визуализаторе

Сценарий «Нормальная работа»: свободные ресурсы помогают сети (relay), нода
публикует capacity. Инспектор показывает включённые capabilities (чипы ✓/✕).
Перегрузка отключает общественные роли (см.
[capacity-and-admission-control](capacity-and-admission-control.md)).

## Открытые вопросы

- Экономика/стимулы участия в общей сети.
- Расписание помощи (например, только ночью или только при зарядке).
