# OUO Home / Desktop Node

> Статус: **концепция + интерактивная модель в визуализаторе**. Реальная реализация
> ноды/протокола здесь не описывается как готовая.

## Назначение

OUO — не централизованный сервис, через который проходит вся коммуникация. Это
продукт для людей, работающий за счёт устройств и нод самих пользователей, без
обязательного центрального хранилища и без единой компании, владеющей перепиской.
Разработчик даёт клиент, протокол и удобные инструменты, но не становится
владельцем сети и данных. Сеть должна пережить исчезновение разработчика.

**OUO Home** — устанавливаемое приложение (Windows/macOS/Linux, мини-ПК, сервер,
NAS, ВМ), которое ставится обычным установщиком. Пользователь не клонирует git,
не правит конфиги и не поднимает контейнеры вручную.

## Сущности (роли внутри одного приложения)

```
OUO Home
├── Desktop Messenger        — общение
├── Home Node Service        — домашняя нода пользователя
├── Personal Storage         — Secure Objects (зашифрованные)
├── File Library             — обычные файлы в проводнике ОС
├── Sync Agent               — синхронизация телефона и ПК
├── Device Pairing           — привязка устройств по QR
├── Optional Relay           — помощь сети (по желанию)
├── Optional Temporary Storage
└── Network Assistance Controller
```

## Привязка телефона (QR)

Телефон подключается к дому одноразовым QR. QR **не** содержит постоянный пароль,
S3-credentials или долгоживущий секрет.

```
1. Home генерирует ключи устройства
2. Показывает одноразовый короткоживущий QR
3. Телефон сканирует
4. Взаимная криптографическая проверка
5. Пользователь подтверждает fingerprint / короткий код
6. Создаётся доверенная связь Phone ↔ Home
7. pairing-token уничтожается
```

Требования: одноразовость и короткое время жизни токена, защита от повторного
использования, взаимная аутентификация, отзыв устройства, журнал устройств.

## Состояния ноды

`created → starting → local_ready → contacting_bootstrap → validating_credentials
→ registering → online`, а также `degraded / offline / blocked`. В контексте
нагрузки/безопасности: `normal / busy / overloaded / critical / offline /
compromised / outdated` (см. [capacity-and-admission-control](capacity-and-admission-control.md)).

## Отказоустойчивость

При выключенном доме часть функций личного облака временно недоступна, но система
не падает — используется fallback (см. [storage-model](storage-model.md) §fallback).

## Реализовано в визуализаторе

Раздел «Безопасность OUO Home»: сцена OUO Home с ролями, привязка телефона
(доверенный канал), сценарии Normal и Home-offline. Простой режим скрывает
термины (Home Node → «Личное хранилище», Relay → «Помогать передавать
сообщения»), экспертный — показывает реальные названия.

## Открытые вопросы

- UX выбора между «личное облако» и «помощь сети» для неподготовленного
