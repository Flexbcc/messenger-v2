# Storage model: Secure Objects, User Library, доставка

> Статус: **модель**. В визуализаторе показаны потоки; реальное S3/шифрование не
> реализовано.

## Разделение хранилищ

```
OUO Storage
├── Secure Objects          — внутреннее защищённое хранилище OUO
│   ├── encrypted blobs
│   ├── manifests
│   ├── indexes
│   ├── thumbnails
│   └── delivery metadata
└── User Library            — обычные папки в проводнике ОС
    ├── Photos / Videos / Documents / Downloads / Shared Files
```

**Secure Objects** — зашифрованные файлы, вложения чатов, служебные объекты,
контрольные суммы, индексы, метаданные доставки, данные репликации.
Компрометация файлового каталога **не** должна автоматически раскрывать переписку.

**User Library** — обычные файлы: фото можно сохранить как JPG, документ открыть
сторонней программой, синхронизировать выбранные папки. Открытая копия менее
защищена, чем объект в Secure Objects.

Настройка входящих файлов: только в защищённое хранилище / автосохранение в
библиотеку / спрашивать для каждого файла.

## Независимые сущности ключей

```
S3 credentials ≠ chat key ≠ file encryption key
User identity ≠ Device identity ≠ Node identity
Transport session ≠ Chat session ≠ Attachment object key ≠ Storage access capability
```

Relay и Storage **не** имеют ключей содержимого. Хранилищу не нужно
регистрировать обоих участников чата — оно отдаёт зашифрованный объект по
capability token / временной подписанной ссылке / ограниченному download token /
авторизованному запросу через Home Node. Ключ расшифрования едет внутри
E2EE-сообщения.

## Доставка сообщения и файла — разные маршруты

Текст: direct encrypted channel → иначе relay → иначе временная зашифрованная
очередь (если получатель офлайн).

Файл (два независимых потока):

```
Message path:  Device A → Node A → Node B → Device B   (E2EE конверт: locator+key)
Media path:    Device A → S3 → Device B                (зашифрованный blob)
```

Порядок доставки файла: локальный ключ объекта → шифрование → manifest → прямая
доставка (если онлайн) и/или доступная копия (Home отправителя → S3 → локальная
очередь) → получатель качает, проверяет hash, расшифровывает локально.

## Fallback (дом выключен)

```
Home Node online?
├── yes → use Home Node
└── no
    ├── S3 configured → temporary S3
    ├── recipient online → direct transfer
    └── otherwise → local pending queue
```

## Реализовано в визуализаторе

Сценарии «Доставка медиа через S3 (два потока)» (раздел Сеть) и «Домашний ПК
выключен — fallback» (раздел Безопасность): видно, что файл не идёт через ноды, а
S3 хранит только зашифрованный объект без ключа.

## Ограничения / открытые вопросы

- Политика дедупликации и репликации объектов.
- Синхронизация выбранных папок и разрешение конфликтов.
