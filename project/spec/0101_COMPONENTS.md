# 0101. Компоненты

## Статус
Черновик

## Назначение
Перечень компонентов системы и их зона ответственности (Single
Responsibility, [[0003_ENGINEERING_PRINCIPLES]]).

## Компоненты

### Клиентские приложения
Отображают интерфейс, хранят данные локально, работают offline-first.
См. [0400_CLIENT.md](0400_CLIENT.md), [0401_FLUTTER.md](0401_FLUTTER.md).

### Core
Кроссплатформенная реализация протокола, криптографии и локального
состояния, общая для клиентов. См. [0500_CORE.md](0500_CORE.md).

### Узлы инфраструктуры

| Компонент | Ответственность | Не отвечает за | Документ |
|---|---|---|---|
| Home Node | Адресация и обслуживание конкретного пользователя, точка входа для входящих пакетов | Хранение истории сообщений, файлы | [0600_HOME_NODE.md](0600_HOME_NODE.md) |
| Relay Node | Пересылка пакетов между узлами/клиентами | Чтение содержимого, долговременное хранение | [0601_RELAY_NODE.md](0601_RELAY_NODE.md) |
| Storage Node | Временная буферизация зашифрованных сообщений для офлайн-получателей | Обработка/чтение содержимого | [0602_STORAGE_NODE.md](0602_STORAGE_NODE.md) |
| Media Node | Хранение и раздача зашифрованных файлов | Хранение переписки, метаданных сообщений | [0603_MEDIA_NODE.md](0603_MEDIA_NODE.md) |
| Discovery Node | Разрешение идентификатора пользователя в адрес Home Node, публикация Capability узлов | Маршрутизация и доставка сообщений | [0604_DISCOVERY_NODE.md](0604_DISCOVERY_NODE.md) |
| Turn Node | Ретрансляция медиапотоков звонков (SRTP), когда P2P невозможен | Сигналинг звонка, чтение содержимого потока | [0605_TURN_NODE.md](0605_TURN_NODE.md) |
| Gateway Node | Публичная точка входа клиента: каталог trusted-нод, bootstrap маршрутизации | Доставка сообщений, расшифровка E2EE | [0606_GATEWAY_NODE.md](0606_GATEWAY_NODE.md) |

Любой физический сервер может совмещать несколько ролей (Node может
публиковать несколько Capability, [[0004_GLOSSARY]]), но внутри реализации
эти роли остаются раздельными модулями — совмещение ролей является
вопросом развёртывания, а не архитектуры.

### Программные слои (сквозные для Core и узлов)
| Слой | Ответственность | Документ |
|---|---|---|
| Crypto Layer | Ключи, шифрование, подписи | [0300_CRYPTO.md](0300_CRYPTO.md) |

| Storage Layer | Персистентность через Repository | [0700_DATABASE.md](0700_DATABASE.md) |

## Матрица взаимодействий
| Инициатор | Получатель | Канал | Что передаётся |
|---|---|---|---|
| Client | Home Node | Protocol | регистрация устройства, отправка/приём Packet |
| Client | Discovery Node | API | разрешение UserID → Home Node |
| Client | Media Node | API | загрузка/скачивание зашифрованных файлов |
| Home Node | Relay Node | Protocol | пересылка Packet к недоступному напрямую Home Node получателя |
| Home Node | Storage Node | Protocol | постановка сообщения в буфер для офлайн-получателя |
| Relay Node | Relay Node | Protocol | multi-hop пересылка (см. [0203_ROUTING.md](0203_ROUTING.md)) |
| Любой Node | Discovery Node | API | публикация собственных Capability |

Ни одна из этих связей не предполагает, что инициатор и получатель
принадлежат одному оператору инфраструктуры (Federation).
