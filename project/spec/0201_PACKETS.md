# 0201. Пакеты

## Статус
Черновик

## Назначение
Формат Packet ([[0004_GLOSSARY]]) протокола: заголовки, сериализация,
лимиты.

## Формат сериализации
Референсный выбор — бинарная схема на базе Protocol Buffers: компактность,
строгая типизация, встроенная поддержка обратной совместимости через
номера полей. Формат сериализации не является частью обязательного
контракта протокола — любая реализация, дающая идентичный канонический
результат (Protocol Before Implementation), допустима.

## Структура пакета
| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `version` | uint16 (`MAJOR.MINOR`) | да | версия протокола, см. [0200_PROTOCOL.md](0200_PROTOCOL.md) |
| `type` | enum | да | тип пакета (см. ниже) |
| `packet_id` | 128-bit UUID | да | уникальный идентификатор пакета, используется для дедупликации (см. [0202_DELIVERY.md](0202_DELIVERY.md)) |
| `session_id` | 128-bit UUID | да | идентификатор Session, к которой относится пакет |
| `sender_ref` | opaque token | нет | одноразовый маршрутизируемый идентификатор отправителя (не Identity напрямую, см. [0203_ROUTING.md](0203_ROUTING.md) → приватность маршрутизации) |
| `timestamp` | int64 (unix ms) | да | время создания пакета отправителем |
| `payload` | bytes | да | зашифрованная полезная нагрузка (см. [0300_CRYPTO.md](0300_CRYPTO.md)) |
| `signature` | bytes (Ed25519) | да | подпись пакета отправляющим узлом (Zero Trust — проверяется получателем на каждом хопе) |

## Типы пакетов
| `type` | Назначение |
|---|---|
| `MESSAGE` | доставка Message |
| `ACK` | подтверждение получения/обработки |
| `HANDSHAKE` | установление Session |
| `PRESENCE` | сигнал доступности устройства (необязательный, может быть отключён из соображений приватности) |
| `DISCOVERY_QUERY` / `DISCOVERY_RECORD` | запрос/ответ разрешения адреса, см. [0604_DISCOVERY_NODE.md](0604_DISCOVERY_NODE.md) |
| `CONTROL` | служебные операции узла (регистрация устройства, ротация ключей) |

Новые типы добавляются без изменения обработки существующих (Backward
Compatibility).

## Ограничения размера
Максимальный размер одного Packet ограничен на уровне транспорта (референс:
64 КБ), чтобы не блокировать мультиплексированный канал. Полезная нагрузка
большего размера (файлы) не передаётся внутри Packet — вместо этого
передаётся ссылка на объект в Media Node (см.
[0102_DATA_FLOW.md](0102_DATA_FLOW.md) → Доставка медиа).

## Обратная совместимость формата
- Поля идентифицируются номером, а не позицией — удаление поля не переиспользует его номер.
- Неизвестные поля игнорируются при разборе, а не приводят к ошибке.
- Любое изменение семантики (не формата) обязательного поля требует новой `MAJOR`-версии.
