# 0401. Flutter-клиент

## Статус
Черновик

## Назначение
Специфика референсной реализации клиента на Flutter — конкретный выбор
инструментов, который можно заменить (Replaceable Everything), не
затрагивая [0400_CLIENT.md](0400_CLIENT.md) или протокол.

## Целевые платформы
iOS, Android, Desktop (Windows/macOS/Linux) из единой кодовой базы Flutter.
Web-таргет рассматривается отдельно из-за ограничений браузерной модели
безопасности для локального защищённого хранилища ключей.

## Структура проекта
Слоистая структура, повторяющая [0400_CLIENT.md](0400_CLIENT.md):
`ui/` (widgets, экраны) → `state/` (управление состоянием) → `core_bridge/`
(мост к Core) — без прямых обращений из `ui/` в `core_bridge/`, минуя
`state/` (Loose Coupling).

## Управление состоянием
Референсный выбор — Riverpod: явные, тестируемые зависимости между
провайдерами состояния упрощают соответствие принципу Testability
([[0003_ENGINEERING_PRINCIPLES]]) — каждый провайдер можно тестировать в
изоляции без поднятия всего приложения.

## Интеграция с Core
Core ([0500_CORE.md](0500_CORE.md)) реализован отдельно от UI-слоя и
подключается через FFI (`dart:ffi` + `flutter_rust_bridge` при
референсной реализации Core на Rust) либо, при необходимости, через
platform channels. Контракт между Flutter-слоем и Core — это стабильный
API (API as Contract), а не набор внутренних деталей реализации Core:
замена Core на другой язык не должна требовать изменений в `ui/` или
`state/`.

## Навигация
Референс — декларативная навигация (`go_router` или эквивалент), с
маршрутами, не зависящими от внутреннего состояния Core.

## Локализация
Строки выносятся в ARB-файлы (`intl`); ни одна строка интерфейса не
хранится внутри Core или протокола — локализация является исключительно
ответственностью Client (Single Responsibility).

## Тестирование
- **Unit-тесты** — для `state/` и адаптеров `core_bridge/`.
- **Widget-тесты** — для отдельных экранов и компонентов UI в изоляции (Testability).
- **Integration-тесты** — для сквозных сценариев (отправка/получение сообщения, офлайн-очередь) на реальном или тестовом Core.
- **Golden-тесты** — для критичных экранов, чтобы визуальные регрессии не проходили незамеченными.
