# 0403. Секретная сессия в чате (Secret Chat Session)

## Статус
Черновик — согласовано с владельцем продукта (2026-07-07)

## Назначение
Временный **секретный режим** внутри обычного 1:1 или группового чата. Не отдельная ветка на сервере, не отдельный Conversation — тот же E2E-поток, клиентская маркировка и фильтрация UI.

Отличается от:
- **[[0402_PRIVATE_MODE]]** — отдельный раздел приложения (PIN, скрытые чаты в сейфе);
- **скрытых чатов** — чаты, убранные из основного списка навсегда (пока не вернуть).

## Принципы
- Сервер и протокол **не меняются** — флаг «секретное» только внутри E2E plaintext (JSON envelope).
- Собеседник видит секретные сообщения **только если сам включил** секретный режим в этом чате.
- Секретные сообщения: **без push**, **без превью** в уведомлениях, **ни при каких условиях**.
- Выход в **список чатов** всегда выключает секретный режим для этого чата.
- Повторный вход в секретный режим — **всегда** с паролем (без «запомнить на N минут»).

---

## Пароль секретной комнаты

### Установка (настройки)
- Произвольная строка (не только 6 цифр): буквы, цифры, пробелы внутри фразы допустимы.
- Хранится на устройстве как **хеш** (Argon2id, тот же класс KDF, что PIN в Private Mode).
- **Запрещено** в пароле: завершающие пробелы; пароль не должен оканчиваться на `  ` (два пробела).
- **Рекомендации при создании** (UI, не блокирующие):
  - длина ≥ 8 символов;
  - не совпадает с типичными фразами переписки («привет», «ок», «да»);
  - не совпадает с отображаемым именем / логином;
  - лучше фраза из нескольких слов.

### Включение режима (в composer любого чата)
Пользователь вводит в поле сообщения:

```
{пароль}␠␠
```

то есть **пароль + ровно два пробела в конце**, затем Enter (отправить).

- Строка **не отправляется** в чат и **не уходит** на сервер.
- При совпадении с хешем пароля — чат переходит в **секретный режим** (локально).
- Двойной пробел в конце — намеренный разделитель вместо спецсимвола (`.`, `#`), чтобы не усложнять ввод.
- Если строка не совпадает — обычная отправка сообщения (в т.ч. текст, случайно оканчивающийся на два пробела, уйдёт как сообщение; риск низкий).

### Выключение режима
| Событие | Действие |
|---------|----------|
| Выход в список чатов (back, tab) | **Всегда** выкл |
| Таймер в чате (настраиваемый) | Выкл по истечении |
| Ручное выкл (кнопка в UI чата) | Выкл |

Таймер: **1 / 2 / 3 / 5 минут** — настраивается в настройках секретной комнаты; отсчёт **только пока пользователь находится в этом чате**. Ушёл в список — таймер сбрасывается вместе с режимом.

## Сообщения

### Обычный режим (секретный выкл)
- Отправка как сейчас — сообщения **без** флага `secret`.
- Видны все несекретные сообщения потока.
- Сообщения с флагом `secret` **скрыты** в ленте.

### Секретный режим (секретный вкл)
- Текст, файлы, фото — тот же transport (E2E ciphertext).
- В JSON envelope plaintext добавляется `"secret": true` (см. ниже).
- Пользователь видит **и** обычные, **и** секретные сообщения в ленте.
- Собеседник видит секретные **только если у него тоже вкл** секретный режим в этом чате.

### Envelope (внутри E2E, без изменения API)

Текст (расширение `MessagePayload`):

```json
{
  "v": 1,
  "body": "текст",
  "secret": true,
  "reply_to": "...",
  "reply_preview": "..."
}
```

Медиа-указатель (image и др.) — поле `"secret": true` в JSON внутри ciphertext.

Сервер хранит только ciphertext — не знает о secret.

### Исчезающие секретные сообщения
- Опциональная настройка: таймер исчезновения **только для secret** (отдельно от обычного disappearing chat).
- Локальное скрытие по времени после расшифровки; политика как у существующего disappearing.

## Уведомления и список чатов

### Push / OS / in-app
- Сообщения с `secret: true`: **никогда** не вызывают push и не показывают превью в уведомлениях.
- In-app banner при активном другом чате — **тоже не показывать** для secret.

### Список чатов (subtitle)
- Если последнее сообщение в чате — secret, а пользователь **не** в секретном режиме в этом чате:
  - показывать **последнее несекретное** сообщение (как agreed).
- Если несекретных не было — нейтральное «Начните переписку» / пустой preview.

### Поиск
- Secret-сообщения не попадают в глобальный поиск, пока секретный режим в этом чате выкл.

---

## UI-индикаторы
- В секретном режиме: явный, но не кричащий индикатор (иконка замка, полоска, subtitle в AppBar).
- В обычном режиме — **никаких** следов, что в чате есть скрытые secret-сообщения (кроме subtitle по правилу выше).

---

## Мультиустройство
- Секретный режим — **состояние сессии на устройстве**, не синхронизируется.
- На каждом устройстве свой ввод `пароль␠␠` для входа в режим.
- Secret-флаг в сообщении синхронизируется через обычную доставку E2E; видимость на другом устройстве — после ввода пароля там.

---

## Связь с Private Mode (0402)
- **Не заменяет** Secret Room / скрытые чаты.
- Пароль секретной сессии может совпадать с PIN Private Mode **только если пользователь сам так настроит** — по умолчанию **отдельные** секреты.
- Fake PIN / decoy — не открывает секретный режим в чате.

---

## MVP-реализация (клиент)
1. `SecretChatSessionStore` — пароль (hash), таймер, политика исчезновения.
2. `ChatScreen` — перехват отправки: `endsWith('  ')` + verify → activate, clear field.
3. `MessagePayload` — `secret` flag encode/decode; фильтр в `visibleMessagesFor`.
4. `sendText` / `sendImage` — выставлять `secret: true` если сессия активна.
5. Уведомления — guard в `_maybeNotifyMessage`.
6. `conversation_list_screen` — subtitle: last non-secret preview.
7. Настройки — пароль, таймер (1/2/3/5), disappearing для secret.

## Открытые вопросы (после MVP)
- Групповые чаты: один секретный режим на всю группу или per-user visibility (сейчас: per-user visibility через локальный режим).
- Паника / блокировка экрана — выкл секретного режима?
- Скриншот-политика для secret (OS-level, ограниченно).
