# 0600. Home node

## Статус
Черновик

## Назначение
Узел, закреплённый за пользователем/устройством и отвечающий за его
адресацию и первичную маршрутизацию входящих сообщений (Home Node,
[[0004_GLOSSARY]]). Может принадлежать самому пользователю, компании или
сообществу — архитектура не делает различий между этими вариантами
(Community Driven Infrastructure, [[0002_PRINCIPLES]]).

## Ответственности
- Регистрация Device пользователя и хранение их публичных Identity.
- Приём входящих Packet, адресованных обслуживаемым пользователям, и их доставка на активные Device (fan-out на все устройства пользователя).
- Публикация собственного адреса в Discovery Node, чтобы другие участники сети могли найти обслуживаемых пользователей.
- Передача Packet на Storage Node, если получатель временно недостижим (см. [0102_DATA_FLOW.md](0102_DATA_FLOW.md)).

Home Node **не хранит** содержимое переписки дольше времени одной
транзакции доставки и **не имеет** доступа к расшифрованному содержимому
Message (Privacy by Default, Single Responsibility).

## Регистрация клиента на home node
Device выполняет Identity handshake (см. [0200_PROTOCOL.md](0200_PROTOCOL.md))
и регистрирует свой публичный ключ на Home Node. Один пользователь может
одновременно зарегистрировать несколько Device; каждое из них получает
независимый поток входящих Packet.

## Взаимодействие с другими узлами
- **Relay Node** ([0601_RELAY_NODE.md](0601_RELAY_NODE.md)) — для доставки к Home Node, с которой нет прямой связности.
- **Storage Node** ([0602_STORAGE_NODE.md](0602_STORAGE_NODE.md)) — для буферизации при недоступности получателя.
- **Discovery Node** ([0604_DISCOVERY_NODE.md](0604_DISCOVERY_NODE.md)) — для публикации собственного адреса и разрешения адресов других Home Node.

## Отказоустойчивость и миграция
Пользователь может сменить Home Node (например, перейти с публичной
инфраструктуры сообщества на собственный Home Node), опубликовав новую
подписанную Discovery-запись со своим Identity-ключом. Старые собеседники
получают актуальный адрес при следующем разрешении адреса, без потери
Identity и истории ключей E2EE, поскольку Identity не привязана к
конкретному Home Node (см. [0004_GLOSSARY.md](0004_GLOSSARY.md) →
Identity).

## Масштабирование
Home Node проектируется как горизонтально масштабируемый сервис за общим
хранилищем метаданных (см. [0700_DATABASE.md](0700_DATABASE.md)): она не
хранит состояние, которое не может быть перенесено между экземплярами —
это позволяет обслуживать от одного пользователя (self-hosted) до
миллионов без изменения архитектуры (Scalability, [[0002_PRINCIPLES]]).
