# 0701. S3-совместимое хранилище

## Статус
Черновик

## Назначение
Объектное хранилище для медиафайлов и вложений, используемое Media Node
(см. [0603_MEDIA_NODE.md](0603_MEDIA_NODE.md)).

## Провайдер
Используется открытый S3-совместимый интерфейс как стандарт (Open
Standards, [[0003_ENGINEERING_PRINCIPLES]]), а не конкретный проприетарный
API. Референсные варианты: MinIO для self-hosted развёртывания, любой
управляемый S3-совместимый сервис (включая AWS S3) — для операторов,
предпочитающих управляемую инфраструктуру. Замена одного провайдера на
другой не требует изменений в Media Node, если оба реализуют один и тот же
открытый интерфейс (Replaceable Everything).

## Структура бакетов
Объекты адресуются по хэшу шифротекста (контентная адресация, см.
[0300_CRYPTO.md](0300_CRYPTO.md) → SHA-256/BLAKE3), а не по
пользовательскому имени файла — это одновременно упрощает дедупликацию
идентичных зашифрованных объектов и не раскрывает исходное имя файла
объектному хранилищу.

## Политики доступа
Доступ к объекту предоставляется через короткоживущие presigned URL,
выпускаемые Media Node после проверки, что запрашивающий Client
действительно является получателем соответствующего Message. Публичных
бакетов с постоянным доступом не существует.

## Шифрование объектов
Объекты уже являются E2EE-шифротекстом на момент загрузки (см.
[0603_MEDIA_NODE.md](0603_MEDIA_NODE.md)); дополнительное серверное
шифрование на стороне хранилища (SSE) применяется как защита в глубину, но
не заменяет клиентское шифрование.

## Политики жизненного цикла (lifecycle)
Автоматическое удаление объектов по TTL, согласованному с политикой
хранения Media Node; опциональный перенос в холодное хранилище для
объектов, которые разрешено хранить дольше стандартного TTL по явному
запросу пользователя.
