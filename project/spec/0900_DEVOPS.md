# 0900. DevOps

## Статус
Черновик

## Назначение
Развёртывание, эксплуатация и наблюдаемость инфраструктуры проекта — как
для крупных операторов, так и для одного пользователя, поднимающего
Home Node самостоятельно (Community Driven Infrastructure,
[[0002_PRINCIPLES]]).

## Окружения
`dev` → `staging` → `production`, плюс отдельно поддерживаемый
**self-host режим** — минимальная конфигурация (например, единый
docker-compose стек с Home Node, Storage Node, Media Node и базой данных),
которую любой пользователь может развернуть без доступа к остальной
инфраструктуре проекта. Self-host режим — не «облегчённая версия», а то
же самое ПО, что и в production, что напрямую следует из принципа «можно
ли поднять этот компонент самостоятельно?» ([0003_ENGINEERING_PRINCIPLES.md](0003_ENGINEERING_PRINCIPLES.md)).

## CI/CD
Пайплайн для любого компонента обязан включать: линтинг, unit-тесты, и
там, где применимо — набор тестов на соответствие протоколу (protocol
conformance suite, см. [0500_CORE.md](0500_CORE.md)). Ни один PR не
может быть смержен, если он меняет поведение Protocol без сопутствующего
изменения [0200_PROTOCOL.md](0200_PROTOCOL.md) и, при необходимости, ADR
(Specification First).

## Инфраструктура как код
Референс: Terraform для облачных ресурсов управляемых развёртываний,
Docker Compose/Kubernetes-манифесты — для узлов инфраструктуры. Конкретный
инструмент заменяем (Replaceable Everything); обязательное требование —
любое production-развёртывание должно быть воспроизводимо из
декларативного описания, а не из ручных шагов.

## Мониторинг и алертинг
Каждый Node экспортирует метрики (референс: Prometheus-совместимый
формат) — задержка обработки Packet, очередь Storage Node, доступность
Relay Node. Алерты настраиваются на отклонения, влияющие на гарантии
доставки (см. [0202_DELIVERY.md](0202_DELIVERY.md)), а не только на
падение процесса (Observability, [[0003_ENGINEERING_PRINCIPLES]]).

## Логирование
Логи включают метаданные обработки (тип Packet, время, идентификаторы
маршрутизации) и никогда — расшифрованное содержимое Message, которое
узел физически не может прочитать (Privacy by Default). Логи
структурированы (JSON или эквивалент) для машинной обработки и
трассировки.

## Управление секретами
Приватные ключи Node (Identity, TLS) никогда не покидают узел, на котором
сгенерированы, и не хранятся в системе управления конфигурацией в
открытом виде — только в выделенном secret-хранилище (например,
Vault-совместимом) с ограниченным доступом.

## План аварийного восстановления (DR)
Для каждого типа Node определена процедура восстановления из бэкапа (см.
[0700_DATABASE.md](0700_DATABASE.md) → Резервное копирование) с измеримыми
целевыми показателями (RTO/RPO), которые периодически проверяются
учебным восстановлением, а не остаются только на бумаге.

## Масштабирование инфраструктуры
Каждый тип Node масштабируется независимо от остальных (Modular
Architecture) — рост числа пользователей на одном Home Node не требует
изменений в Relay Node или Media Node, и наоборот. Подробности по каждому
типу узла — см. [0600_HOME_NODE.md](0600_HOME_NODE.md) и далее.
