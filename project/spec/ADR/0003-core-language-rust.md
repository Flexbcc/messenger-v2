# 0003. Референсный Core на Rust с FFI-биндингами

## Статус
Accepted

## Дата
2026-07-05

## Контекст
Core ([0500_CORE.md](../0500_CORE.md)) реализует протокол и криптографию
и должен быть переиспользуем между разными клиентскими платформами
(мобильные, десктоп, потенциально серверные компоненты) без дублирования
логики на каждом языке отдельно (Loose Coupling, DRY по духу Single
Responsibility).

## Рассмотренные варианты
1. **Реализовать Core отдельно на каждом языке клиента** (Dart, Kotlin, Swift) — максимальная нативность, но прямое нарушение принципа «не дублировать логику»: любое изменение протокола пришлось бы вносить в N реализаций синхронно, что на практике быстро расходится.
2. **Единый Core на Rust с FFI-биндингами** (`flutter_rust_bridge` и эквиваленты для других платформ) — одна реализация протокола и криптографии, переиспользуемая из разных клиентов через стабильный API-контракт.
3. **Core на языке виртуальной машины (например, Kotlin Multiplatform)** — тоже единая реализация, но менее зрелая экосистема кроссплатформенных биндингов на момент принятия решения и более слабые гарантии безопасности памяти для криптографического кода, чем у Rust.

## Решение
Выбран вариант 2. Rust выбран из-за безопасности памяти без сборщика
мусора (важно для кода, работающего с ключами и расшифрованным
содержимым) и зрелой экосистемы FFI. Это решение реализации, а не
требование протокола — любая другая реализация Core на другом языке,
проходящая protocol conformance suite, остаётся полностью совместимой
(см. [ADR-0001](0001-protocol-first-architecture.md)).

## Последствия
- Flutter-клиент подключает Core через `dart:ffi` (см. [0401_FLUTTER.md](../0401_FLUTTER.md)).
- Публичный интерфейс Core → Client фиксируется как стабильный контракт (API as Contract), чтобы смена языка Core в будущем не потребовала переписывания UI-слоя.
- Команде необходима экспертиза в Rust для развития Core — принятый компромисс ради безопасности памяти и переиспользуемости.
