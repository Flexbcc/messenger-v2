# 0012. Языки реализации нод: Python для control plane, Rust для hot path

## Статус
Accepted

## Дата
2026-08-19

## Контекст
Текущие сервисы нод реализованы на Python 3.11, FastAPI и asyncio. Проекту
одновременно нужны быстрые итерации, воспроизводимые тесты, безопасность
памяти и возможность в будущем обрабатывать большой поток бинарных cells.

ADR-0004 описывал TypeScript как язык MVP-сервисов, однако фактическая
реализация была создана на Python. Этот ADR заменяет только языковую часть
ADR-0004 и приводит решение в соответствие с работающим кодом.

## Рассмотренные варианты
1. **Python для всех слоёв.** Быстрая разработка и зрелый сетевой стек, но
   ограниченная эффективность CPU-bound Mix/Sphinx/erasure-code обработки.
2. **C для всех слоёв.** Высокая предсказуемая производительность, но высокий
   риск ошибок управления памятью, более дорогая разработка и большая
   поверхность атак для сетевого сервиса, разбирающего недоверенные данные.
3. **Python control plane + Rust hot path.** Python сохраняет скорость
   разработки API и orchestration; Rust используется там, где измерения
   показывают необходимость нативной скорости и контроля памяти.

## Решение
Выбран вариант 3.

- Discovery, Gateway, Home orchestration, административные API и первая
  реализация Relay/Storage/TURN остаются на **Python 3.11**.
- Node Identity, сертификаты и wire-объекты сначала реализуются как
  спецификация и совместимый Python reference module.
- CPU-bound transport core (binary batches, Sphinx-like processing, K-of-N,
  Mix Pool) переносится в **Rust** только после профилирования и с сохранением
  protocol conformance suite.
- **C не используется для нового application-level сетевого кода.** Допустимы
  только проверенные нативные библиотеки, подключённые через поддерживаемые
  bindings и изолированные стабильным API.
- Переписывание работающего сервиса допускается только при наличии benchmark,
  нагрузочного профиля и тестов совместимости протокола.

## Последствия
- Текущий кластер можно развернуть без предварительного переписывания нод.
- Надёжность определяется fail-closed validation, лимитами, persistence,
  тестами и наблюдаемостью, а не только языком.
- Наиболее опасный для memory-safety код не переносится в C.
- Появляется обязанность держать wire protocol независимым от Python/Rust и
  прогонять одинаковые conformance vectors для обеих реализаций.
