# simulation — настройки симуляции сети

Симуляция прогоняет настройки остальных проектов и показывает их эффект.
Делит единый источник истины с клиентом:
[`../../ouo-settings-web-spec`](../../ouo-settings-web-spec) (тот же
`ouo-settings-spec.json`). Модели поведения — в
`../../ouo-settings-web-spec/docs/{live-simulation,visualizer-scenarios}.md`.

## Две группы «настроек» симуляции
1. **Настройки-вход (что симулируем)** — реальные настройки проектов, которые
   симуляция читает и применяет:
   - клиент: `node.*` (выбор ноды/fallback/relay), `storage_ownership.*`,
     `privacy/security` там, где влияет на доставку;
   - нода: network-assistance роли, capacity/admission (§ client-node docs);
   - сеть: heartbeat-порог, обновления, реакция на уязвимости (§ backend docs).
   Расхождений с `ouo-settings-spec.json` быть не должно.

2. **Настройки-стенд (как симулируем)** — параметры самого прогона (не из спеки):
   топология, отказы, задержки, версии нод — в сценарии.

## Формат сценария (черновик)
См. `../scenarios/example.yaml`:
- `nodes` — сколько нод каждого типа и версии;
- `events` — отказы/сообщения/подключения во времени (`at_s`);
- `assert` — ожидаемый результат (напр. `delivered: true`).

Расширяемые оси (roadmap):
- профили network-assistance и лимиты capacity на community-нагрузку;
- задержки/потери relay, NAT, LAN-vs-relay для storage-app;
- раскатка обновлений с проверкой подписи и downgrade-защиты;
- пометка версии уязвимой → карантин.

## Связи
- `live-simulation.md` — что визуализатор анимирует.
- Один каталог настроек с `../../frontend` — симуляция это «клиент под нагрузкой».
