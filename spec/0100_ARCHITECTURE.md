# 0100. Архитектура

## Статус
Черновик

## Назначение
Общее описание архитектуры системы верхнего уровня: из каких больших частей
она состоит и как они взаимодействуют. Детальная разбивка — в
[0101_COMPONENTS.md](0101_COMPONENTS.md), потоки данных — в
[0102_DATA_FLOW.md](0102_DATA_FLOW.md), сетевая топология — в
[0103_NETWORK.md](0103_NETWORK.md).

## Обзор системы
Платформа (Platform, [[0004_GLOSSARY]]) состоит из четырёх слоёв,
независимых друг от друга (Modular Architecture, Loose Coupling):

```
┌───────────────────────────────────────────────────────────┐
│ Client (0400)                                              │
│   UI  →  Core (0500, через FFI/SDK)                        │
└───────────────────────────────────────────────────────────┘
                         │  Protocol (0200)
                         ▼
┌───────────────────────────────────────────────────────────┐
│ Infrastructure nodes (0600–0604)                            │
│  Home │ Relay │ Storage │ Media │ Discovery                 │
│  (независимые, федерируют друг с другом)                    │
└───────────────────────────────────────────────────────────┘
                         │
                         ▼
┌───────────────────────────────────────────────────────────┐
│ Storage Layer (0700–0701): Database │ S3-compatible storage │
└───────────────────────────────────────────────────────────┘
```

Клиент никогда не обращается к базе данных или объектному хранилищу
напрямую — только через Protocol и API узлов (Single Responsibility).

## Архитектурные слои
- **Клиент** ([0400_CLIENT.md](0400_CLIENT.md), [0401_FLUTTER.md](0401_FLUTTER.md)) — интерфейс пользователя, локальное шифрованное хранилище, работает offline-first.
- **Core** ([0500_CORE.md](0500_CORE.md)) — кроссплатформенная реализация протокола и криптографии, общая для всех Client и, где применимо, для реализаций Node.
- **Протокол** ([0200_PROTOCOL.md](0200_PROTOCOL.md) и далее) — открытая спецификация, не зависящая от языка реализации.
- **Узлы инфраструктуры** ([0600_HOME_NODE.md](0600_HOME_NODE.md) и далее) — независимые сервисы с одной ролью каждый (Single Responsibility), совместно образующие федеративную сеть.
- **Хранилище** ([0700_DATABASE.md](0700_DATABASE.md), [0701_S3.md](0701_S3.md)) — заменяемый слой персистентности за Repository-интерфейсами.

## Кросс-слойные принципы
- Между любыми двумя слоями существует только один документированный интерфейс (API as Contract).
- Ни один слой не хранит больше данных о другом слое, чем необходимо для своей роли (Privacy by Default, Zero Trust).
- Любой слой можно заменить целиком, не переписывая соседние (Replaceable Everything) — критерий проверки: см. чек-лист в [0003_ENGINEERING_PRINCIPLES.md](0003_ENGINEERING_PRINCIPLES.md).

## Ограничения и допущения
- Протокол проектируется в предположении ненадёжной сети и недоверенных промежуточных узлов (см. [0300_CRYPTO.md](0300_CRYPTO.md) → Модель угроз).
- Ни один компонент архитектуры не предполагает существования единственного оператора инфраструктуры.
- Референсная реализация (Rust-ядро, Flutter-клиент, PostgreSQL/SQLite, S3-совместимое хранилище) — один из возможных вариантов, а не обязательное требование протокола.
