# 0603. Media node

## Статус
Черновик

## Назначение
Узел, отвечающий за приём, хранение и раздачу медиавложений (изображения,
видео, файлы, голосовые сообщения) — Media Node
([[0004_GLOSSARY]]). Media Node не обязан хранить сообщения — это
отдельная ответственность от Storage Node (Single Responsibility).

## Ответственности
- Приём зашифрованных на клиенте файлов и их сохранение в объектном хранилище.
- Раздача зашифрованных файлов по запросу авторизованного получателя.

## Шифрование медиа
Файл шифруется на Client отправителя до загрузки; ключ файла передаётся
получателю только внутри E2EE-конверта Message (см.
[0300_CRYPTO.md](0300_CRYPTO.md)). Media Node хранит и раздаёт исключительно
шифротекст и никогда не получает ключ расшифровки — с точки зрения Media
Node содержимое файла неотличимо от случайных данных.

## Ограничения размера и типов файлов
Ограничения размера являются параметром конкретного развёртывания, а не
частью протокола. Крупные файлы передаются потоково/чанками, чтобы не
требовать полной буферизации файла в памяти ни на клиенте, ни на узле.

## Обработка медиа (превью, транскодирование)
Поскольку Media Node не имеет доступа к содержимому, генерация превью и
транскодирование (если требуются) выполняются на Client до шифрования —
Media Node не выполняет обработку контента, который не может прочитать
(Privacy by Default).

## Хранение
Media Node использует S3-совместимое объектное хранилище как бэкенд (см.
[0701_S3.md](0701_S3.md)); сам Media Node — это тонкий сервис
авторизации доступа и адресации объектов поверх этого хранилища, а не
самостоятельная файловая система.

## CDN и раздача
Поскольку раздаваемые объекты уже зашифрованы end-to-end, они безопасно
кэшируются на границе сети (CDN/edge) без риска раскрытия содержимого —
кэширование ускоряет раздачу, не расширяя круг сторон, способных прочитать
файл.

## Политики хранения и удаления
Объект удаляется по политике TTL, аналогичной Storage Node, либо по
явному запросу отправителя на удаление (если это предусмотрено
Conversation), либо после подтверждения получения всеми адресатами —
конкретная политика конфигурируется на уровне развёртывания.
