# 0800. API

## Статус
Черновик

## Назначение
Публичные и внутренние API системы: клиент-сервер и сервис-сервис. API
([[0004_GLOSSARY]]) — контракт между компонентами, не определяющий их
внутреннюю реализацию (API as Contract,
[[0003_ENGINEERING_PRINCIPLES]]).

## Внешний API (клиент ↔ инфраструктура)
Два разных канала с разной природой:
- **Data plane** — обмен Packet между Client и Home Node по [0200_PROTOCOL.md](0200_PROTOCOL.md) (бинарный протокол поверх QUIC/TCP, см. [0103_NETWORK.md](0103_NETWORK.md)).
- **Control plane** — операции, не являющиеся обменом сообщениями: регистрация Device, привязка нового устройства, запросы к Discovery Node, получение presigned URL от Media Node. Референс — gRPC или HTTP/2 с protobuf-схемами, версионируемыми независимо от Protocol.

## Внутренний API (узел ↔ узел)
Node обмениваются Packet по тому же Protocol, что и Client (Protocol
Before Framework — нет отдельного «внутреннего» протокола, скрытого от
внешних реализаций). Служебные операции (публикация Capability в
Discovery Node, репликация Discovery-записей) используют тот же
control-plane подход, что и внешний API.

## Аутентификация и авторизация API
Аутентификация построена на criptографическом challenge-response с
использованием Identity-ключа (Device или Node), а не на паролях или
статичных API-ключах (Zero Trust, [[0003_ENGINEERING_PRINCIPLES]]).
Авторизация конкретной операции (например, скачивание объекта с Media
Node) проверяется через короткоживущие подписанные токены, выпущенные
после успешной аутентификации.

## Версионирование API
Control-plane API версионируется независимо от версии Protocol, по той же
схеме `MAJOR.MINOR` (см. [0200_PROTOCOL.md](0200_PROTOCOL.md)). Client и
Node согласуют поддерживаемую версию при установлении соединения.

## Ограничение частоты запросов (rate limiting)
Каждый узел применяет rate limiting на уровне соединения независимо от
остальной сети (Stateless Communication) — параметры лимитов являются
настройкой конкретного развёртывания, а не частью протокола.

## Обработка ошибок
Ошибки возвращаются в структурированном виде: машиночитаемый код ошибки +
человекочитаемое описание. Коды ошибок стабильны в рамках `MAJOR`-версии
API (Backward Compatibility) — существующий код ошибки не меняет смысл
между `MINOR`-версиями.

## Документация и контракты
Схемы control-plane API (protobuf/OpenAPI) хранятся в репозитории рядом
со спецификацией и покрываются контрактными тестами — документация не
может разойтись с фактическим поведением API незамеченно (Specification
First, [[0003_ENGINEERING_PRINCIPLES]]).
